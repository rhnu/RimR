# 界面规范

## 方向

保持紧凑、清晰的桌面工具界面，让用户能同时查看较多模组并完成排序。不以重构为由重新设计视觉风格；沿用现有主题变量、基础组件和三栏排序工作区。

排序页以未启用列表、启用列表和详情区域为主。顶栏放全局菜单，工具栏放当前列表的主要操作；详细信息与次要操作进入上下文菜单、顶栏菜单、详情面板或对话框，避免在每行重复展示大组按钮。

## 形状、间距与颜色

- 默认直角；`rounded-slight` 仅用于按钮和区域边界。禁止胶囊徽章和大圆角卡片。
- 优先使用紧凑行高、小字号、细边框与明确对齐。增加信息密度时保留可识别的点击区域、截断和悬停说明。
- 颜色使用 `styles.css` 中的语义变量与浅／深色主题。不要为单个页面另造一套硬编码色板。
- 选择、悬停、焦点、拖放位置和诊断状态应能区分。颜色只作辅助，错误与警告同时使用图标或文字。
- 列表中的标签用克制的颜色标记表达，详细名称和管理操作留在菜单中，不把整行变成标签集合。

## 交互

单击用于选择和查看详情，双击与上下文菜单提供启用、停用等快捷动作；批量操作应覆盖当前选中范围。菜单打开时保持操作目标明确，不能出现显示选中多项却只处理一项的意外行为。

拖放必须提供清晰插入位置，并区分列表条目、分组及子项。不能通过过滤后的行号猜测底层条目位置；展示顺序与实际提交顺序应一致。筛选用于查找，不应暗中重排已保存顺序。

Save 与 Apply 保持独立入口和状态提示。应用、游戏／存档同步等操作用预览说明结果；重置、删除等丢弃行为使用明确的目标与操作文案。不要把诊断变成禁止应用的隐性门槛。

## 组件与状态

复用 `components/ui` 的菜单、对话框、按钮、滚动区和输入组件；共享行为修正在共同组件内。列表和详情使用真实加载、空数据、失败及重试状态，不能用静态示例掩盖尚未读取的数据。

菜单与对话框保留键盘导航、焦点样式、正确的关闭与焦点返回行为。图标按钮提供可访问名称，输入有标签或明确的可访问说明，长名称不得遮挡操作入口。界面文案统一通过英语与简体中文翻译资源提供。

## 验证

界面变更后检查浅色与深色主题、两种语言、长名称、空列表、缺失模组和加载失败状态。排序交互还需检查多选、过滤、分组子项和拖放位置，确认视觉预览与最终草稿一致。窗口缩到允许的最小尺寸时，主要操作仍应可达，面板内部滚动不能撑破工作区。
