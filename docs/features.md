# 使用说明

## 配置与扫描

首次使用时，在初始设置中自动检测路径，检查后保存并扫描。以后可以在设置页面修改路径，再在排序页面重建模组目录。

| 路径          | 用途                                                                     |
| ------------- | ------------------------------------------------------------------------ |
| 游戏目录      | RimWorld 安装位置，包含官方内容的 `Data` 目录                            |
| 游戏数据目录  | 包含 `Config`、`Saves` 和玩家日志的用户数据位置                          |
| 本地模组目录  | 本地安装的模组，通常是游戏目录下的 `Mods`                                |
| 创意工坊目录  | Steam 下载的 RimWorld 模组，通常位于 `steamapps/workshop/content/294100` |
| RimR 数据目录 | RimR 保存列表、别名和标签的位置                                          |

自动检测提供候选路径，不能保证每种自定义安装位置都正确。游戏目录与游戏数据目录都配置后才能扫描。使用“文件 → 打开”可以定位已配置目录。

扫描读取官方内容、本地模组和创意工坊模组的 `About/About.xml`。详情显示作者、支持版本、描述和加载规则；文件信息用于查看实际安装位置、大小和修改时间。重建目录用于重新读取安装变化，不会自动改写游戏顺序。

## 编辑与使用列表

在排序页面选择或新建列表，通过拖放、双击或上下文菜单在启用与未启用区域之间移动模组，并调整启用区域的顺序。新建列表以已安装的官方内容为起点；“另存为”复制当前列表结构。

列表包含三种条目：

- 模组：保留启用状态和对应的 package ID。
- 分组：按子项顺序组织模组，可以逐项启用、停用或解组。
- 分隔线：标记列表中的区域，可以命名，不会写入游戏加载顺序。

分组应用到游戏时，只在原位置展开已启用的子项。未启用项和分隔线都不进入 `ModsConfig.xml`。

| 操作                 | 结果                                                           |
| -------------------- | -------------------------------------------------------------- |
| 保存                 | 保存当前 RimR 列表，不修改游戏配置                             |
| 应用                 | 预览并确认后，将当前草稿的有效顺序写入游戏配置，不自动保存列表 |
| 重置／放弃更改       | 丢弃当前草稿，回到已保存列表                                   |
| 从游戏顺序同步       | 预览后，用 `ModsConfig.xml` 的顺序更新草稿                     |
| 从存档同步／导入存档 | 读取存档中的模组 ID，预览后更新草稿                            |

“未保存”与“未应用”是不同状态。你可以应用未保存的草稿，也可以保存尚未应用的列表。同步预览会说明添加、移除、移动，以及分组拆分、分隔线位置调整等结构变化。

## 别名、标签与搜索

通过模组上下文菜单编辑显示别名和标签。别名改变 RimR 中的显示，不会改写模组元数据或 package ID。别名和标签按 package ID 共享；模组在本地目录和创意工坊之间移动后仍可关联。

标签可以命名、着色、删除和调整顺序。颜色条用于快速识别标签；详细操作放在标签菜单中。

搜索不区分大小写；多个条件必须同时满足。普通文字匹配名称、package ID、作者、别名等信息。

| 写法         | 含义                         | 示例                               |
| ------------ | ---------------------------- | ---------------------------------- |
| `#文字`      | 标签名包含文字               | `#战斗`                            |
| `&来源`      | 匹配来源                     | `&workshop`、`&local`、`&official` |
| `@文字`      | 所在分组名包含文字           | `@基础`                            |
| `!条件`      | 排除匹配结果                 | `!#停用`                           |
| `"多个单词"` | 将包含空格的文字作为一个条件 | `#"Quality of Life"`               |

`steam` 与 `workshop` 表示创意工坊；`official`、`expansion` 与 `dlc` 表示官方内容。例如 `#战斗 &workshop !@备用` 查找带战斗标签、来自创意工坊、且不在备用分组中的模组。

## 诊断与缺失模组

RimR 根据 `About.xml` 中的依赖、`loadAfter`、`loadBefore`、`forceLoadAfter`、`forceLoadBefore` 和 `incompatibleWith` 检查当前顺序，也读取对应游戏版本的 `*ByVersion` 字段。诊断包含依赖缺失或未启用、顺序冲突、循环依赖、互斥项、重复 package ID 和元数据读取问题。

诊断不会自动重排列表，也不会阻止应用。请结合模组说明和实际游戏结果判断。顺序正确不等于模组运行时一定兼容。

启用的模组若在 `supportedVersions` 中声明的版本不包含当前游戏主、次版本，会显示警告，同时列出当前游戏版本与模组声明的支持版本。例如游戏为 `1.6.4633`，模组支持 `1.6` 即匹配；只支持 `1.4、1.5` 则警告。未声明可用支持版本或无法识别游戏版本时，不判定为不支持。该提示只反映作者的版本声明，不代表实际运行一定不兼容。游戏版本优先从安装目录的 `Version.txt` 读取，失败时尝试 `ModsConfig.xml` 中的版本；后者可能滞后于安装版本。游戏更新后应重建模组目录以刷新判断。

未安装但仍被列表或游戏配置引用的模组会显示为缺失。应用时跳过缺失项并报告；可以安装对应模组后重建目录，或通过清理缺失项操作从草稿中移除它们。保留缺失项有助于暂时卸载后恢复列表。

同一个 package ID 可能存在多个安装副本。RimR 报告重复项并使用扫描选出的副本；当前没有副本选择界面。打开目录、查看文件和清理针对实际来源位置，详情中的来源可帮助确认。

## 导入、导出与存档

文件菜单支持导入、导出 RimR 模组列表和库设置。列表文件保留模组、分组和分隔线；库设置文件用于交换别名和标签。导入库设置会合并内容，匹配项采用导入值，其余本地项保留。导出列表以已保存版本为准，要包含草稿修改应先保存。

RimR 的 `.rimr.json` 文件包含管理数据或游戏配置备份，不包含模组文件，不会下载缺失模组。导入不会直接改写游戏配置；要在游戏中使用顺序，仍需明确执行应用。

存档导入读取普通 XML、gzip 或 zstd 压缩的 RimWorld 存档中的模组 ID。它只恢复存档记录的顺序，不恢复模组文件、分组或标签，也不修改存档。较旧或没有模组元数据的存档可能没有可导入的 ID。

## 日志与文件工具

“帮助 → 关于 RimR”打开简洁对话框，显示项目简介、作者、许可证和 GitHub 入口，底部列出运行中的 RimR 版本与检测到的 RimWorld 版本。打开对话框会重新读取游戏版本，不要求先扫描模组；路径未配置或版本文件不可用时显示“未检测到”，读取失败时显示相应状态。

日志页面可以查看 Steam 创意工坊安装记录，以及游戏的 `Player.log` 和 `Player-prev.log`。游戏日志支持搜索、级别筛选、引用跳转和实时刷新；创意工坊记录可按名称、ID 或 package ID 搜索。

工具菜单可以检查仅剩纹理的无效模组和元数据无效的模组目录。先核对候选项，再确认清理；清理会将候选目录移到系统回收站。模组上下文菜单还提供打开安装目录、Steam 或创意工坊网页的入口。

## 数据存放与启动迁移

RimR 数据目录默认是用户文档目录下的 `RimR`；无法取得文档目录时使用用户主目录下的 `RimR`。可以在设置中指定其他位置。当前库快照保存在其中的 `current/library.json`；路径配置独立保存在平台应用配置目录下的 `current/config.json`。主题与语言是本机偏好，不随库设置文件交换。

启动时会自动检测并转换旧配置和旧库，将全部列表、别名、标签及其引用写入新的存储位置。旧文件保持原样。迁移只在尚未建立当前数据时执行，后续启动使用新数据，不持续合并旧文件中的修改。

迁移发现损坏或缺失的数据时会停止并显示原因；已有新数据损坏也不会被旧文件自动覆盖。请保留原文件，按错误中给出的路径排查或恢复备份，处理后重新启动。旧 `.rimr.json` 文件仍可通过文件菜单手动导入。

## 常见问题

- **扫不到模组：**检查游戏目录是否指向安装根目录，本地与创意工坊路径是否指向各模组文件夹的上一级，然后重建目录。
- **读不到游戏顺序或日志：**检查游戏数据目录，而不是安装目录；确认游戏已创建相应文件。
- **应用后游戏顺序不符：**确认应用成功且配置的是当前游戏使用的数据目录；关闭游戏后再应用，避免游戏退出时写回自己的顺序。
- **模组仍显示旧信息：**重建模组目录；清除会话缓存用于重新读取运行期间的缓存数据，不等于删除已保存列表。
- **导入失败：**确认文件类型正确、JSON 完整且版本受支持。保留原文件，不要用空文件替代故障数据。

Windows 是主要支持平台。其他平台的路径检测和桌面集成仍属实验性支持；自定义 Steam、Proton 或受隔离的安装可能需要手动设置路径。
